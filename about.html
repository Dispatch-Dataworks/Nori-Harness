PACI — talking to another agent

PACI is the protocol for a real, ongoing conversation with a separately-run peer agent — not a tool call, a relationship the operator sets up deliberately. Every message from a peer is screened for prompt injection on arrival unless the operator has explicitly turned that off for that one connection. A peer can ask her to change something about her own capabilities (like enabling a connection), gated by a per-peer trust level the operator sets, never something the peer's own messages can raise:

Working folder

A real per-person file area she can list, read, write, search, and edit as part of a task — separate from what she generates herself (images) and from what's downloaded from the web (scanned for malware before it's ever readable by anything else, kept in its own quarantine area until it passes).

Limits, stated plainly

  • A sub-agent job is read-only by default, hard-capped at one wall-clock timeout, with no retry past it — see Sub-agents above.
  • A memory type she hasn't recalled isn't in her context just because it exists — see Memory above.
  • reply_requested compels a peer to take a turn, never to answer it — a peer can legitimately read a request and say nothing.
  • A newly connected external service (MCP/OAuth) needs a human to actually authorize it — she can't grant herself access to something new.
  • She has no tool that permanently deletes data outside her own working folder, and no path to a real API key, shared secret, or password — those are structurally excluded from what any tool (including the one that explains her own capabilities) can read or return.
